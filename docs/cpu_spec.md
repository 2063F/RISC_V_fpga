# RISC_V_fpga CPU 仕様書

Tang Primer 25K 上で動く、自作の 32 ビット RISC-V CPU (2 ハート) の仕様です。
合成結果は 2026-11-28 のタイミングレポート (Gowin EDA V1.9.12.02_SP2、
`othello.hex` を載せた `fpga_top`) によります。

## 1. 概要

| 項目 | 内容 |
|:--|:--|
| 命令セット | RV32IMAC + Zicsr + Zifencei (`misa` = `0x40001105`) |
| 特権モード | マシンモード (M) のみ |
| ハート数 | 2 (`cpu_top` の `NUM_HARTS` = 1 または 2。`fpga_top` は 2) |
| パイプライン | 3 段 (IF / ID / EX)、インオーダー、1 命令ずつ発行 |
| 動作クロック | 50 MHz (最大 50.492 MHz) |
| 命令メモリ | ROM 32 KB (BSRAM、2 ポート、ビットストリームで初期化) |
| データメモリ | RAM 32 KB (BSRAM) |
| キャッシュ | なし |
| 浮動小数点 | なし (ソフトウェアで計算) |
| 割り込み | タイマ・ソフトウェア (ハートごと)、外部 (UART 受信。hart 0 のみ) |
| 記述言語 | Verilog (Icarus Verilog でシミュレーション、Gowin EDA で合成) |
| ターゲット | Sipeed Tang Primer 25K (Gowin GW5A-LV25MG121NC1/I0) |

## 2. ブロック構成

```
                ┌──────────── cpu_top (SoC) ─────────────┐
  ┌────────┐ IF │ ┌──────────────┐                         │
  │ hart 0 │────┼─│ 命令 ROM     │ ポート A: hart 0 の命令  │
  │rv_core │    │ │ 32 KB 2 ポート│ ポート B: hart 1 の命令 │
  └───┬────┘    │ └──────────────┘  (hart 1 停止中は      │
  ┌────────┐ IF │        │           .rodata の読み出し)   │
  │ hart 1 │────┼────────┘                                 │
  │rv_core │    │                                          │
  └───┬────┘    │                                          │
      │ データバス (共有・ラウンドロビン調停・AMO 実行)      │
      ├─────────┼─ データ RAM 32 KB                         │
      │         ├─ UART (115200 bps)                        │
      │         ├─ タイマ (mtime / mtimecmp / msip)         │
      │         ├─ ハート起動レジスタ                       │
      │         └─ mem_* ポート ─────────────────────────┐ │
      │         └──────────────────────────────────────┼─┘
      │                                                 │
      │  fpga_top: board_io ─ LED・ボタン・キーマトリクス・ │
      │            LED マトリクス・USB キーボード・VGA ───┘
```

| モジュール | 役割 |
|:--|:--|
| `rv_core.v` | ハート 1 個分。パイプライン、レジスタファイル、ALU、乗算器、除算器、CSR |
| `rvc_expand.v` | 16 ビット命令を同じ意味の 32 ビット命令に展開 |
| `cpu_top.v` | SoC。ハート、ROM、RAM、UART、タイマ、バス調停、アドレスデコード、AMO 実行 |
| `fpga_top.v` | FPGA トップ。`cpu_top`、`board_io`、LED マトリクス、VGA、USB キーボード、リセット |

## 3. 命令セット

| 拡張 | 命令 | 数 |
|:--|:--|--:|
| RV32I | LUI, AUIPC, JAL, JALR, 分岐 6, ロード 5, ストア 3, 即値演算 9, レジスタ間演算 10, FENCE, ECALL, EBREAK | 40 |
| M | MUL, MULH, MULHSU, MULHU, DIV, DIVU, REM, REMU | 8 |
| A | LR.W, SC.W, AMOSWAP/ADD/XOR/AND/OR/MIN/MAX/MINU/MAXU.W | 11 |
| Zicsr | CSRRW, CSRRS, CSRRC, CSRRWI, CSRRSI, CSRRCI | 6 |
| 特権 | MRET, WFI | 2 |
| Zifencei | FENCE.I | 1 |
| C | RV32C のうち浮動小数点以外の全命令 | — |

- FENCE・FENCE.I・WFI は何もしない (キャッシュがなく、ROM は書き換えられないため。WFI を NOP とするのは仕様上許される)
- 上記以外のエンコーディングは不正命令例外
- `aq` / `rl` ビットは何もしない (メモリが逐次一貫のため)
- C 拡張のため、命令は 2 バイト境界に置ける。32 ビット命令がワードをまたいでもよい
- C の推奨オプション: `-march=rv32imac_zicsr -mabi=ilp32`

## 4. パイプライン

| 段 | 処理 |
|:--|:--|
| IF | PC で命令 ROM を読む (1 ワード単位)。ROM の出力レジスタが IF/ID レジスタを兼ねる |
| ID | 命令の整列 (前のワードの上位 16 ビットを保持して組み立て)、C 展開、デコード、即値生成、レジスタファイル読み出し |
| EX | ALU・乗算器・除算器、分岐判定、メモリアクセス、CSR、トラップ判定、書き戻し |

- **データハザード:** EX の書き戻し値から ID の読み出しへのフォワーディング 1 本で全ケースを解決 (間に入る命令は常に 1 つ)
- **制御ハザード:** 分岐・ジャンプは EX で確定。成立すると後続 2 命令を破棄
- **レジスタファイル:** 32 × 32 ビット、非同期読み出し 2 ポート、同期書き込み 1 ポート。x0 は常に 0

### 命令ごとのサイクル数 (待ちなし)

| 命令 | サイクル数 |
|:--|:--|
| ALU 演算・LUI・AUIPC・CSR | 1 |
| 分岐 (不成立) | 1 |
| 分岐 (成立)・JAL・JALR | 3 (後続 2 命令を破棄) |
| ロード | 2 |
| ストア | 1 (RAM 以外へのストアの直後の 1 サイクルは、次のアクセスを受け付けない) |
| MUL / MULH / MULHSU / MULHU | 3 |
| DIV / DIVU / REM / REMU | 34 |
| LR.W | 2 |
| SC.W・AMO*.W | 4 |
| トラップ・MRET | 3 (分岐成立と同じ) |

- ジャンプ直後に、ワードの上位 16 ビットから始まる 32 ビット命令に当たったときだけ 1 サイクル余分にかかる
- 2 ハートが同時にデータバスを使うと、待たされた側は 1 サイクル以上遅れる

## 5. メモリマップ

| アドレス | 内容 | アクセス |
|:--|:--|:--|
| `0x0000_0000` - `0x0000_7FFF` | 命令 ROM 32 KB (リセットベクタ 0 番地) | 命令フェッチ、データ読み出し (hart 1 動作中は 0 が読める) |
| `0x0001_0000` - `0x0001_7FFF` | データ RAM 32 KB (`0x0001_8000` - `0x0001_FFFF` は同じ RAM の折り返し) | 読み書き (バイト・ハーフワード・ワード) |
| `0x8000_0010` | UART TX データ | 書き込み |
| `0x8000_0014` | UART TX 状態 (bit 0 = 送信中) | 読み出し |
| `0x8000_0018` | UART RX データ (読むと受信済みフラグを解除) | 読み出し |
| `0x8000_001C` | UART RX 状態 (bit 0 = 受信データあり) | 読み出し |
| `0x8000_0020` | オンボード LED 制御 (bit 0) | 読み書き |
| `0x8000_0024` | ユーザーボタン S2 (bit 0) | 読み出し |
| `0x8000_0028` | キーマトリクス行出力 (bit 7:0、アクティブ Low、リセット値 `0xFF`) | 読み書き |
| `0x8000_002C` | キーマトリクス列入力 (bit 7:0、押すと 0) | 読み出し |
| `0x8000_0030` / `0034` | LED マトリクス緑ビットマップ 下位 / 上位 32 ビット (bit = 行 × 8 + 列) | 読み書き |
| `0x8000_0038` / `003C` | LED マトリクス赤ビットマップ 下位 / 上位 | 読み書き |
| `0x8000_0040` | USB キーボード: 読み出しで bit 9 = 接続、bit 8 = イベントあり、bit 5:0 = キー番号。書き込みでイベントを消費 | 読み書き |
| `0x8000_0044` / `0048` | VGA ヒント (黄色の点) ビットマップ 下位 / 上位 | 読み書き |
| `0x8000_004C` | VGA 制御: bit 0 = 盤面表示 (リセット値 1)、bit 1 = 赤緑の石 | 読み書き |
| `0x8000_0050` | VGA 直前の手: bit 6 = 有効、bit 5:0 = マス | 読み書き |
| `0x8000_0100` - `0x8000_013F` | タイマ (ハートごとに 0x20 バイト。6 章) | ワードのみ |
| `0x8000_0200` | ハート起動: bit 1 = hart 1 を動かす (bit 0 は常に 1) | 読み書き |
| `0x8000_1000` - `0x8000_1FFF` | VGA テキスト: `0x8000_1000 + 行 × 128 + 列` (80 × 30 字)、bit 6:0 = 文字、bit 7 = 黄色 | 書き込みのみ |

上記以外のアドレスへのアクセスは例外にならない (ロード・ストアのアクセスフォールトは未実装)。

## 6. CSR・例外・割り込み

### CSR

| CSR | 内容 |
|:--|:--|
| `mstatus` | MIE (bit 3)、MPIE (bit 7)。MPP (bit 12:11) は常に 11 |
| `misa` | `0x40001105` (RV32IMAC)。書き込みは無視 |
| `mie` / `mip` | MSIE/MSIP (bit 3)、MTIE/MTIP (bit 7)、MEIE/MEIP (bit 11)。`mip` は読み出し専用 |
| `mtvec` | BASE + MODE (0: direct、1: vectored。vectored では割り込み N を BASE + 4N へ)。リセット値 0 |
| `mscratch` / `mepc` / `mcause` / `mtval` | トラップ用。`mepc` は bit 1 まで保持 |
| `mcycle` / `minstret` (+ `h`) | 64 ビットカウンタ (書き込み可) |
| `cycle` / `time` / `instret` (+ `h`) | 読み出し専用。`time` はタイマの `mtime` |
| `mvendorid` / `marchid` / `mimpid` | 0 |
| `mhartid` | 0 または 1 |

未実装の CSR へのアクセスと、読み出し専用 CSR への書き込みは不正命令例外。

### 例外

| `mcause` | 例外 | `mtval` |
|:--|:--|:--|
| 1 | 命令アクセスフォールト (ROM の外をフェッチ) | PC |
| 2 | 不正命令 | 命令 (16 ビット命令なら上位 0) |
| 3 | EBREAK | PC |
| 4 / 6 | ロード / ストアのアドレス非整列 (LR は 4、SC・AMO は 6) | アドレス |
| 11 | ECALL | 0 |

### 割り込み (`mcause` bit 31 = 1)

| コード | 割り込み | 要因 / 解除 |
|:--|:--|:--|
| 11 | マシン外部 (hart 0 のみ) | UART に受信データがある間。RX データを読むと解除 |
| 3 | マシンソフトウェア | `msip` = 1 の間。0 を書くと解除 |
| 7 | マシンタイマ | `mtime >= mtimecmp` の間。`mtimecmp` を進めると解除 |

- 優先順位: 外部 > ソフトウェア > タイマ
- トラップは EX で取る。EX の命令を取り消し (レジスタ・メモリ・CSR・MMIO への書き込みをすべて抑止)、`mepc` にその PC を入れ、後続 2 命令を破棄
- 割り込みは命令が EX に入った最初のサイクルでだけ受け付ける。ロード・ストアをバスに出した命令や、乗除算を始めた命令は完了させる

### タイマ (ハート h のブロック = `0x8000_0100 + 0x20 × h`)

| オフセット | レジスタ |
|:--|:--|
| `+0x00` | `msip` (bit 0) |
| `+0x08` / `+0x0C` | `mtimecmp` 下位 / 上位 (リセット値は全ビット 1) |
| `+0x10` / `+0x14` | `mtime` 下位 / 上位 (全ハート共通) |

`mtime` は 50 クロックごとに 1 進む (1 µs)。他のハートの `msip` を 1 にするとコア間割り込みになる。

## 7. データバスと 2 ハート

### バスプロトコル

ハートは EX から一度に 1 つの要求を出し、完了まで信号を保持する。

| 信号 | 向き | 意味 |
|:--|:--|:--|
| `dbus_req` | ハート → SoC | ロード / ストアが受け付け待ち |
| `dbus_pend` | ハート → SoC | トラップ判定前の `dbus_req` (調停用。レジスタから直接出る) |
| `dbus_gnt` | SoC → ハート | 次のクロックで受け付ける。ストアはこれで完了 |
| `dbus_rvalid` / `dbus_rdata` | SoC → ハート | ロードのデータ (サイズ・符号拡張済み) |
| `dbus_amo` / `dbus_amo_op` | ハート → SoC | LR / SC / AMO の種類 (funct5)。rs2 は `dbus_wdata` |

- 全スレーブは受け付けの 1 サイクル後に答える。ロードはデータを返すまでバスを占有する
- 同時要求はラウンドロビン (前回負けた方が優先) で、どちらも飢餓にならない
- キャッシュがなく、各ハートのアクセスはプログラム順に実行されるので、メモリは逐次一貫

### アトミック命令

SoC がバスを占有したまま、読み出し・演算・書き込みを行う (その間、他のハートのアクセスは入らない)。

- 予約はハートごとに 1 ワード。もう一方のハートがそのワードに書き込むと消える
- SC は予約が有効なら書き込んで rd = 0、無効なら書かずに rd = 1。どちらでも予約は消える

### 2 つ目のハート

- hart 1 はリセットされたまま待機し、hart 0 が `0x8000_0200` の bit 1 に 1 を書くと 0 番地から動き出す。bit 1 を 0 に戻すと再びリセット
- ROM のポート B は、hart 1 の停止中は `.rodata` の読み出し用、動作中は hart 1 の命令フェッチ用
- **hart 1 の動作中は ROM からのデータ読み出しが 0 になる。** hart 1 を使うプログラムは `tools/link_mp.ld` でリンクし、`.rodata` を RAM に置く (`crt0.S` がコピー)
- `crt0.S` は `mhartid` ≠ 0 なら初期化を飛ばし、hart 0 のスタックの `__hart_stack_size` 下に自分のスタックを置いて `hart_main(hartid)` を呼ぶ
- UART 受信割り込みは hart 0 だけに届く

## 8. クロックとリセット

| クロック | 周波数 | 用途 |
|:--|:--|:--|
| `sys_clk` | 50 MHz (外部発振器、E2 ピン) | CPU と周辺すべて。VGA はクロックイネーブルで 25 MHz |
| `clk_usb` | 12 MHz (PLL) | USB ホスト (`usb_hid_host`)。50 MHz 側とは同期化回路でつなぐ |

| リセット要因 | 範囲 |
|:--|:--|
| ボタン S1 (H11) | CPU と周辺 |
| USB キーボードの Space を 3 秒押し続ける | S1 と同じ。Space を離すまでリセットを保持 |

リセット後は hart 0 が 0 番地から実行する。`mtvec` は 0 なので、ハンドラを設定する前のトラップは 0 番地に戻る。
RAM のうち `.noinit` セクションはリセットで消えない (電源を切るまで保持)。

## 9. 周辺

| 周辺 | 仕様 |
|:--|:--|
| UART | 115200 bps、8N1 (分周 434)。USB-C (BL616 デバッガ) 経由で PC とつながる |
| キーマトリクス | 8 × 8。CPU が行を 1 本ずつ Low にして列を読む (列は内部プルアップ) |
| LED マトリクス | 8 × 8 2 色 (LTP-12188M-07)。ビットマップを書くと回路が 1/64 デューティで走査する |
| USB キーボード | ロースピード USB 1.1 ホスト (nand2mario 氏の `usb_hid_host`)。押したキーを 1 回のイベントにして MMIO に渡す |
| VGA | 640 × 480 @ 60 Hz、各色 1 ビット (抵抗 DAC)。オセロ盤 (56 ドットのマス、石・ヒント・直前の手) と 80 × 30 字のテキスト (8 × 16 ドット) を重ねて表示 |
| オンボード LED | LED[0]: 約 1.5 Hz の点滅 (クロック動作中)。LED[1]: ソフトウェアの LED 制御レジスタ |

## 10. 合成結果

### リソース

| リソース | 使用量 | 使用率 |
|:--|:--|--:|
| ロジック (LUT + ALU) | 11,074 / 23,040 (LUT 9,857、ALU 1,217) | 49% |
| レジスタ | 4,974 / 23,280 | 22% |
| CLS | 8,171 / 11,520 | 71% |
| BSRAM | 49 / 56 (SP 16、pROM 33) | 88% |
| DSP | MULT12X12 × 2、MULTADDALU12X12 × 1、MULT27X36 × 4 | 36% |
| I/O ポート | 54 / 86 | 63% |
| PLL | 1 / 6 | 17% |

### タイミング

| クロック | 制約 | 最大周波数 | 論理段数 |
|:--|--:|--:|--:|
| `sys_clk` | 50.000 MHz | 50.492 MHz | 13 |
| `clk_usb` | 12.000 MHz | 123.873 MHz | 7 |

- セットアップ・ホールドとも違反 0 (TNS 0)。解析パス 20,612、エンドポイント 16,559
- 最小セットアップスラック: +0.195 ns。最小ホールドスラック: +0.247 ns
- 遅いパスは主に 2 種類:
  1. 命令 ROM の出力 → hart 1 の ID (C 展開・デコード・フォワーディング) → `ex_alu_b` / `ex_rs2_data` (最悪 +0.195 ns)
  2. hart 1 の `ex_alu_op` → アドレス計算 → `board_io` の読み出しデータ (`io_bridge/read_data`、+0.298 ns)
- 解析条件: セットアップ Slow 0.873 V 0 °C、ホールド Fast 0.927 V 85 °C

## 13. 制限事項

- マシンモードのみ (ユーザーモード、仮想記憶、PMP なし)
- 浮動小数点、キャッシュ、分岐予測なし
- ロード・ストアのアクセスフォールトは未実装 (存在しないアドレスへのアクセスは例外にならない)
- 命令は ROM からのみ実行でき、実行中に書き換えられない (Zifencei の自己書き換えテストは対象外)
- hart 1 の動作中は ROM のデータを読めない
- メモリは BSRAM の ROM・RAM 各 32 KB のみ (SDRAM は計画中。`docs/sdram_plan.md`)
- タイミングの余裕が小さい (+0.195 ns)。回路を足すときは遅いパスに注意
